16  Repository Structure

This page is a navigational reference for the City Scan codebase. It maps every top-level directory and key file to its purpose, so you know where to look — and what to edit — when something needs fixing or adjusting. For how these pieces connect at runtime (task orchestration, inter-module calls, CLI flags), see task-dependency.qmd.

city-scan/
├── tasks/               # per-topic data collection, analysis, and visualization modules
├── core/                # shared infrastructure: Python utilities, R functions, CLI
├── source/              # canonical config files copied into each city folder on first run
├── inputs/              # user-provided config and AOI for the current scan
├── mnt/                 # auto-generated per-city output folders
├── scan-calculations/   # Quarto project that assembles per-task outputs into a report
├── templates/           # boilerplate starters to copy into inputs/
├── docs/                # this documentation site
├── notebook/            # exploratory Jupyter notebooks (unmaintained)
├── old_docs/            # archived documentation and CHANGELOG
├── logs/                # run logs (auto-created on first run)
├── bootstrap.sh         # one-time system dependency installer (macOS / Linux / WSL)
├── orchestrator.sh      # Python venv setup via pyenv
├── pyproject.toml       # package metadata and `scan` CLI entry point
└── requirements.txt     # Python dependencies

16.1 tasks/

tasks/
├── __main__.py          # CLI entry point: parses flags, dispatches to core/config/run.py
├── __init__.py          # package init
├── contributing.md      # task contribution guide
├── <task_name>/
│   ├── __init__.py      # registers collect(), analyze(), visualize() entry points
│   ├── collection.py    # downloads and clips data to AOI  (.py or .R)
│   ├── analysis.py      # computes statistics and generates CSVs  (.py or .R)
│   ├── maps.yml         # [optional] map layers this task contributes + custom map scripts
│   ├── multianalysis.R  # [optional] cross-task R post-processing (e.g. flood exposure)
│   └── charts/          # [optional] Quarto charts rendered into the scan-calculations report
│       ├── _quarto.yml
│       └── index.qmd
└── ...

Tasks present in the repo (36 modules): accessibility air_quality basic_info buildings burned_area coastal_erosion cyclones demographics earthquake elevation fathom flood_events forest fwi gdp_gridded gdp_sectoral ghs_builtup ghs_population groundwater landcover landcover_burn landslide liquefaction lst ndxi nightlight oxford rwi sea_level_rise seismic_hazard slope solar water_risk worldpop wsf

For what each task produces, see the Tasks & Data Layers section:

Population & Demographics · Economic Activity · Built Form · Climate Conditions · Risk Identification

  • Tasks are auto-registered via source/tasks.yml
  • Task dependencies and the orchestration graph are documented in task-dependency.qmd

16.2 core/

16.2.1 core/config/

core/config/
├── scan.py        # Scan class: loads AOI, reads city config, creates city output folders in mnt/
├── auth.py        # GEE and GCS authentication (tiered: existing creds → gcloud ADC → fail-fast)
├── paths.py       # auto-detects input/output directories based on project structure
├── tasks.py       # task registry (reads source/tasks.yml)
├── cli.py         # CLI flag parsing — single source of truth for all flags
├── run.py         # run_task(), run_multicity() execution logic
├── multitask.py   # parallel task runner with TUI for --parallel flag
├── inputs.py      # prepare_inputs(): stages user inputs into the city folder
├── sync.py        # sync_project_files() for --sync flag
├── check_env.py   # environment preflight for --check flag
├── gdal_auth.py   # configures GDAL for /vsigs/ access to private GCS buckets
└── utils.py       # shared slugify() and other helpers

16.2.2 core/py/

core/py/
├── log_module.py          # logging setup (console + rotating file output)
├── error_tracker.py       # counts errors per task; surfaces OK / WARNING / ERROR / NO_DATA status
├── gcs_module.py          # GCS upload/download, file tracking for --upload flag
├── aoi_module.py          # detects country name(s) and ISO3 codes from AOI intersection
├── aoi_buffer.py          # AOI buffer utilities in meters for OSM queries
├── aoi_helper.py          # AOI geometry helper functions
├── osm_client.py          # unified OSM access (routes to Geofabrik PBF or Overpass by AOI size)
├── osm_pbf.py             # Geofabrik PBF download + attribute filter helpers
├── gee_fns.py             # GEE tiling helpers (make_tiles, tiled_collection)
├── raster_module.py       # raster mosaic, masking, GCS-safe operations
├── check_layers.py        # validates layer outputs against expected spec
├── clean.py               # shared data-cleaning utilities
└── convert_shp_to_fgb.py  # shapefile → FlatGeobuf conversion helper

16.2.3 core/R/

core/R/
├── setup.R              # R session init: loads packages, reads AOI, sets directory paths
├── fns.R                # core shared functions (plot_static_layer, cell_aggregate, h3_aggregate, …)
├── fns-*.R              # extended function libraries — 10 files covering:
│                        #   aggregation, charts, geometry, maps-aes, maps-static,
│                        #   maps-web, population, text, utilities, web
├── pre-mapping.R        # data preprocessing before mapping (combine flood zones, WSF edits, …)
├── pre-charting.R       # data preprocessing before chart rendering
├── maps-static.R        # orchestrates static map generation: standard loop + custom scripts
├── maps-web.R           # web map rendering
├── map-*.R              # custom map scripts for layers needing special handling (13 files):
│                        #   building-footprints, coastal-erosion, deforestation, economic-activity-*,
│                        #   elevation, flooding, gdp-flood, ghs-expansion, historical-burnt-area,
│                        #   intersections, isochrones, schools-health-proximity,
│                        #   sectoral-gdp-flood, seismic-hazard
├── chart-*.R            # chart generators per data type (13 files):
│                        #   age-sex-distribution, earthquakes, elevation, flood-archive,
│                        #   flooding, fwi, groundwater, landcover, slope, solar-pv, urban-extent
├── data-*.R             # data processing helpers (6 files):
│                        #   coastal-erosion, collection, flood-wsf-probability,
│                        #   gridded-gdp, slr-clip, wsf-harmonized
├── benchmark-assembly.R # benchmark city assembly
├── benchmark-helper.R   # benchmark city selection and Oxford lookup (diacritic-insensitive)
├── gcs-auth.R           # GCS authentication for R
├── gcs-overrides.R      # per-city GCS path overrides
├── pop-backup.R         # population fallback functions (UN data, citypopulation.de, GHS-POP)
├── population-growth.R  # population growth rate calculations
├── write-population.R   # writes population outputs
├── global-data-paths.R  # data path configuration shared across R scripts
├── clean-tabular.R      # tabular data cleaning
├── pdf-prep.R           # PDF export preparation
├── plots.R              # shared plotting utilities
├── rename-generic.R     # layer/file renaming helpers
├── in_design.R          # design system utilities
└── transparencies.R     # color and transparency configuration
  • Edit map-*.R to customise the rendering of specific layers
  • Edit fns.R / fns-*.R for shared plotting and aggregation logic
  • maps-static.R is the orchestration entry point for all static maps

16.2.4 core/ojs/

core/ojs/
├── dataloader.js   # data-loading utilities for Observable JS charts
└── plots.js        # D3-based interactive chart definitions used in the web report

16.3 source/

source/
├── layers.yml                           # map layer styling: palettes, breaks, labels, fuzzy_string per layer
├── tasks.yml                            # task registry: auth requirements, aliases, dependencies
├── generic-text.yml                     # report text templates per section
├── countries_economies_classification.csv  # country/economy classification lookup
├── slide-list.csv                       # slide/report section configuration
├── output-check.qmd                     # Quarto quality-assurance template
├── pagedtable-fix.scss                  # Bootstrap table styling overrides
└── pagedtable.css                       # paged table base styles
  • These files are copied into each city folder on first run
  • Edit layers.yml to adjust map symbology; edit tasks.yml to change task auth or dependencies
  • generic-text.yml holds the boilerplate narrative text that appears in scan reports

16.4 inputs/

inputs/
├── city_inputs.yml   # single-city config: name, AOI, year ranges, flood/accessibility/benchmark params
├── multi_inputs.yml  # multi-city batch config: city list (or multipolygon file) + shared settings
├── menu.yml          # toggle which tasks to enable or disable
└── AOI/              # boundary shapefile(s) for the city or cities
  • User-facing configuration for each new scan — not tracked in git
  • Copy from templates/ and edit before running; see inputs-config.qmd for field reference

16.5 mnt/

mnt/
└── <scan-id>/                   # e.g. 2026-03-morocco-rabat
    ├── 01-user-input/           # copy of inputs/ staged for this scan
    ├── 02-process-output/
    │   ├── spatial/             # rasters and vector files (.tif, .gpkg, .fgb)
    │   └── tabular/             # CSVs and statistics
    ├── 03-render-output/
    │   ├── maps/                # static map PNGs
    │   └── plots/               # chart PNGs
    ├── tasks/                   # synced copy of tasks/ for this scan
    ├── core/                    # synced copy of core/
    ├── source/                  # synced copy of source/
    └── scan-calculations/       # synced copy of scan-calculations/
  • City output folders are auto-created per scan by the Scan class
  • Each city gets an isolated copy of tasks/, core/, source/, scan-calculations/ so scans are reproducible without re-syncing

16.6 scan-calculations/

scan-calculations/
├── _quarto.yml       # Quarto project config
├── sections.yml      # defines which tasks appear in the report and in what order
├── generate-index.R  # reads sections.yml and assembles per-task qmds into index.qmd
└── ...               # per-task chart qmds assembled at render time
  • Quarto project that compiles per-task charts/index.qmd files into a single combined HTML report
  • sections.yml is the place to reorder or exclude tasks from the final report

16.7 templates/

templates/
├── city_inputs.yml   # starter single-city config
├── multi_inputs.yml  # starter multi-city config
├── menu.yml          # starter task menu
├── manual-text.md    # starter manual narrative text
└── README.md         # template usage notes
