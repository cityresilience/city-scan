\markboth{Welcome}{Welcome}

The City Scan is a diagnostic tool designed to equip cities with the
early insights needed to address risk by:

\begin{itemize}
\tightlist
\item
  Providing a rapid, data-driven snapshot of a city's demographic,
  economic, climate, and risk landscape.
\item
  Leveraging remote sensing and geospatial analysis of any city in the
  world, using global datasets.
\item
  Revealing the interaction between the urban built and natural
  environments.
\end{itemize}

\subsection*{In this technical
reference}\label{in-this-technical-reference}
\addcontentsline{toc}{subsection}{In this technical reference}

This reference book is a structured technical documentation to use and
operate City Scan as a diagnostic tool. Here, you will find
documentations on City Scan overview, getting started, running a City
Scan, tasks and data layers, repository structure, case studies \&
galleries, as well as contributing guides.

\chapter{What is City Scan?}\label{what-is-city-scan}

\begin{figure}[H]

{\centering \includegraphics[width=0.6\linewidth,height=\textheight,keepaspectratio,alt={High-level conceptual illustration of the City Scan system.}]{image/concept.jpg}

}

\caption{City Scan Concept}

\end{figure}%

A City Scan is a rapid geospatial assessment of a city's demographic,
socioeconomic, climate, and risk conditions. It is a collection of maps
and charts made from global and publicly available datasets that provide
quick high-level insights into resilience-related topics for a city. The
output is a package of maps, data visualizations and insights that
integrate features of both the built and natural environments. These
scans are especialy useful for grounding early-stage conversations in
geospatial data.

\section{What can the City Scan tell
me?}\label{what-can-the-city-scan-tell-me}

This City Scan is intended to support operational teams in building
dialogue around a city's most pressing resilience challenges. It is
designed as a conversation starter rather than a specific decision
making tool. Thinking spatially about how urbanization affects the
resilience of various urban forces, networks, and people helps equip
officials to develop risk informed investment proposals, identify
opportunities and barriers to unlocking private capital, and prioritize
and coordinate future investments.

\section{Guiding questions to keep in
mind}\label{guiding-questions-to-keep-in-mind}

\begin{itemize}
\tightlist
\item
  How might investment priorities differ in different parts of the city
  based on this data?
\item
  What spatial relationships are surprising?
\item
  What questions does this spatial pattern spur?
\item
  Where else have you worked that is reminiscent of these findings?
\item
  What might be applicable from there? What might not be?
\end{itemize}

\section{Why invest in urban
resilience}\label{why-invest-in-urban-resilience}

Investing in urban resilience boosts long-term economic, social, and
physical sustainability by safeguarding the gains from current
developments for future generations. Greater urban resilience builds the
capacity of local governments to help households, communities, and
enterprises manage and avoid shocks and stresses, for example by
damage-proofing infrastructure before a disaster or maintaining critical
services afterward. This approach represents a significant shift from
prior development trends, which concentrated investments on
post-disaster reconstruction and recovery.

\section{Part 3. Running a Scan}\label{part-3.-running-a-scan}

When running a scan, we are essentially going through several phases.
The general flow is collect → analyze → multianalysis → render.

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\item
  \href{running-first-cityscan.qmd}{\textbf{Collect}} stage is
  retrieveing specified datasets as indicated in inputs configuration
  from various publicly available sources for the specified AOI. As an
  output, you will retrieve TIFFs, GeoJSONs, or Geopackages in your
  output folder.

  To conduct \textbf{collect} stage, run in your terminal

\begin{Shaded}
\begin{Highlighting}[]
\ExtensionTok{scan} \AttributeTok{{-}{-}collect}
\end{Highlighting}
\end{Shaded}
\item
  \href{running-first-cityscan.qmd}{\textbf{Analyze}} stage is
  conducting various analysis on a single task, such as seeing the
  statistical distribution, applying threshold, extracting median/mean
  values, etc. As an output, you will retrieve various CSVs in your
  output folder.

  To conduct \textbf{analyze} stage, run in your terminal

\begin{Shaded}
\begin{Highlighting}[]
\ExtensionTok{scan} \AttributeTok{{-}{-}analyze}
\end{Highlighting}
\end{Shaded}
\item
  Alternatively, you can \textbf{batch data collection and data analysis
  together by looping over tasks} by running:

\begin{Shaded}
\begin{Highlighting}[]
\ExtensionTok{scan} \AttributeTok{{-}{-}all}
\end{Highlighting}
\end{Shaded}

  Or, you can leverage your computer memory and \textbf{parallelizing
  data collection and data analysis together per tasks} by running:

\begin{Shaded}
\begin{Highlighting}[]
\ExtensionTok{scan} \AttributeTok{{-}{-}all} \AttributeTok{{-}{-}parallel}
\end{Highlighting}
\end{Shaded}
\end{enumerate}

\begin{enumerate}

\item
  \href{running-first-cityscan.qmd}{\textbf{Multianalysis}} stage is
  performing cross-task analysis after single tasks analysis have been
  executed. For example, this stage executes analysis of flood-exposed
  population, which requires both flood analysis and population analysis
  to have been conducted. To do this, run in your terminal:

\begin{Shaded}
\begin{Highlighting}[]
\ExtensionTok{scan} \AttributeTok{{-}{-}multianalysis}
\end{Highlighting}
\end{Shaded}
\item
  \href{running-first-cityscan.qmd}{\textbf{Render}} stage is generating

  rendering maps and charts as PNGs or HTMLs.

\begin{Shaded}
\begin{Highlighting}[]

\begin{Highlighting}[]

\end{Highlighting}
\end{Shaded}

and web visualization.

All City Scan tasks can be accessed through terminal with the required
tools configured:

\begin{itemize}
\tightlist
\item

\section{Authentication}\label{authentication}

Authentication is managed in \texttt{core/config/}:

\begin{itemize}
\tightlist
\item
  \textbf{\texttt{auth.py}} --- initializes Google Earth Engine (GEE)
  and Google Cloud Storage (GCS) credentials
\item
  \textbf{\texttt{scan.py}} --- the Scan class that loads AOI, city
  config, and creates city output folders
\item
  \textbf{\texttt{paths.py}} --- auto-detects input/output directories
  based on project structure
\item
  \textbf{\texttt{gdal\_auth.py}} --- configures GDAL for authenticated
  access to private GCS buckets via \texttt{/vsigs/}
\end{itemize}

Tasks that need GEE (forest, landcover, LST, NDVI, nightlight) or
private GCS (WSF, fathom, landcover burn, basic info) are automatically
authenticated before running. If auth fails, those tasks are skipped
with a warning.

\section{Quarto}\label{quarto}

Quarto is a publishing system that lets you create documents and
websites with R, Python, JavaScript, and Julia. If you are familiar with

similar but allows for the use of multiple languages in the same
document. It is used to create the City Scan reports and website.

A Quarto file is a markdown document with code chunks that can be
rendered into HTML, PDF, or other formats. The Python and R code is
executed at the time of rendering and the output is included in the
final document.

To install Quarto, follow the instructions at

\subsection{Step 4: Running Tasks}\label{step-4-running-tasks}

\emph{Make sure the Python environment is activated}.

Executing tasks can be done from the \texttt{city-scan} directory or
from within \texttt{mnt/scan-id}. General form:

\begin{verbatim}
scan {TASKNAME} {FLAG}
\end{verbatim}

Each task is divided into different steps, defined by \texttt{\{FLAG\}}:
- \textbf{\texttt{-\/-collect}} runs data collection and saves outputs
in \texttt{02-process-outputs/spatial} or \texttt{/tabular} -
\textbf{\texttt{-\/-analyze}} runs data analysis and creates output CSVs
in \texttt{02-process-outputs/tabular} - \textbf{\texttt{-\/-all}} runs
both \textbf{\texttt{-\/-collect}} and \textbf{\texttt{-\/-analyze}},
reads \texttt{menu.yml} - \textbf{\texttt{-\/-multianalysis}} runs
cross-task analysis (currently only for fathom)

To run all tasks set to true in \texttt{menu.yml} in parallel
(recommended):

\begin{verbatim}
scan --all 
\end{verbatim}

This opens a Terminal UI (TUI) showing per-task progress and logs.

When running the above from - \textbf{\texttt{city-scan}} root ---
initializes \texttt{mnt/scan-id} and copies all necessary folders. - For
an existing scan, target it with \texttt{-\/-scan-id}:
\texttt{scan\ -\/-all\ -\/-parallel\ -\/-scan-id\ 2026-02-malta-malta} -
Inside \textbf{\texttt{mnt/scan-id}} --- outputs files into the local
\texttt{02-process-outputs/}.

To run an individual task or a set of tasks:

\begin{verbatim}
# Individual task
scan wsf

# Multiple tasks
scan wsf population forest
\end{verbatim}

Run specific steps with \texttt{\{FLAG\}}:

\begin{verbatim}
# Collect step only
scan wsf --collect

# Analyze step only for multiple tasks
scan wsf population green --analyze
\end{verbatim}

Other available flags:

\begin{verbatim}
# Show available tasks
scan --list

# Re-run using the city's existing code (no resync from root)
scan --all -k --scan-id 2026-02-malta-malta
\end{verbatim}

\subsection{Step 4b: Multi-analysis}\label{step-4b-multi-analysis}

Some tasks have cross-task analysis scripts (e.g.~flood exposure
calculations that combine flood and WSF data). Run these after all
individual tasks have completed:

\begin{verbatim}
scan --all --multianalysis
\end{verbatim}

\section{Rendering Maps and Charts}\label{rendering-maps-and-charts}

\subsection{Step 5: Rendering Maps and
Charts}\label{step-5-rendering-maps-and-charts}

After data collection and analysis, generate maps and charts via the
\texttt{-\/-render} flag:

\begin{verbatim}
# Static maps — applies styling from source/layers.yml, writes PNGs to 03-render-output/maps/
scan --render maps --scan-id 2026-02-malta-malta

# Charts for a specific task — writes HTML to tasks/{name}/charts/index.html
scan --render charts elevation --scan-id 2026-02-malta-malta
\end{verbatim}

Maps read spatial data from \texttt{02-process-output/spatial/}. Charts
read CSVs from \texttt{02-process-output/tabular/}.

\subsection{Step 6: Scan Calculations Reference
Sheet}\label{step-6-scan-calculations-reference-sheet}

The \texttt{scan-calculations} reads \texttt{sections.yml} to determine
section order, then assembles all per-task \texttt{charts/index.qmd}
into a single combined HTML report:

\begin{verbatim}
scan --render scan-calculations --scan-id 2026-02-malta-malta
\end{verbatim}

The compiled report is saved to
\texttt{scan-calculations/scan-calculations.html}.

If \texttt{scan\_calculations:\ True} is set in \texttt{menu.yml}, the
scan-calculations folder is automatically copied to the city folder when
running \texttt{scan\ -\/-all}.

See
\href{../../scan-calculations/README.md}{scan-calculations/README.md}
for details.
