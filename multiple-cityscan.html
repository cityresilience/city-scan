7  Running Multiple Cities

While a single-city run processes one city at a time, the --multicity flag lets you queue a list of cities and run them sequentially from a shared configuration file. Setup is similar, but inputs are organized per city rather than in a flat folder.

There are two ways to provide city boundaries for a multi-city run. Both use the same inputs/multi_inputs.yml config file and the same scan --all --multicity command.

7.1 Option A: Separate AOI Folders

Best when you already have individual shapefiles per city.

7.1.1 Step 1. Create inputs/multi_inputs.yml

This file follows the same structure as city_inputs.yml, with a cities: list added at the top.

cities:
  - city_name: Windhoek
  - city_name: Swakopmund
  - city_name: Walvis Bay
  - city_name: Lüderitz
  - city_name: Aus

# Shared settings — same fields as city_inputs.yml
first_year: 2015
last_year: 2026

flood:
  threshold: 15
  year: [2020]
  return_period: [10, 100, 1000]

# ... accessibility, FWI, etc.

All settings outside the cities: list are shared across every city. You can override any shared setting for a specific city by adding it under that city’s entry:

cities:
  - city_name: Windhoek
    first_year: 2010    # overrides the shared first_year for Windhoek only
  - city_name: Aus

7.1.2 Step 2. Organize AOI files by city

Each city needs its own subfolder under inputs/AOI/. Place the shapefile and its companion files (.dbf, .prj, .shx) inside that subfolder:

inputs/AOI/
  Windhoek/
    Windhoek_geoboundaries.shp
    Windhoek_geoboundaries.dbf
    ...
  Swakopmund/
    Swakopmund.shp
    ...
  Walvis_Bay/
    walvis_buffer_hull_1000m.shp
    ...

If a city has ward boundaries, place them in a sibling folder named {city_name}_wards/:

inputs/AOI/
  Windhoek/
    Windhoek_geoboundaries.shp
    ...
  Windhoek_wards/
    Windhoek_wards_geoboundaries.shp
    ...

Wards are auto-detected — no extra configuration needed.

7.1.3 Step 3. Edit inputs/menu.yml

The same menu.yml is used for all cities. Enable or disable tasks there as usual.

7.2 Option B: Multipolygon File

Best when all city boundaries are already in a single vector file (GPKG, SHP, or GeoJSON), with one row per city. AOI shapefiles are extracted automatically from the file into inputs/AOI/{city_slug}/ — you don’t need to prepare them manually.

7.2.1 Step 1. Create inputs/multi_inputs.yml

Instead of organizing AOIs into subfolders, point to the multipolygon file and specify which column holds the city names:

multipolygon:
  file: inputs/AOI/lobito_corridor_cities.gpkg
  name_column: GC_UCN_MAI_2025

# Shared settings — same as Option A
first_year: 2015
last_year: 2026

flood:
  threshold: 15
  year: [2020]
  return_period: [10, 100, 1000]

By default, all cities in the file are processed. To run only a subset, add a cities: list — all AOIs are still extracted, but only the listed cities are scanned:

multipolygon:
  file: inputs/AOI/lobito_corridor_cities.gpkg
  name_column: GC_UCN_MAI_2025

cities:
  - city_name: Sakania
  - city_name: Lukuni
Note

If a city listed under cities: is not found in the multipolygon file, an error is raised.

7.2.2 Step 2. Edit inputs/menu.yml

Same as Option A — one shared menu.yml for all cities.

7.3 Running

scan --all --multicity

Cities are always processed sequentially. All other flags work as expected:

scan --all --multicity --parallel      # parallel tasks within each city
scan --all --multicity --collect       # collect step only, all cities
scan wsf fathom --multicity            # specific tasks for all cities
scan --all --multicity --upload        # upload to GCS after each task

# Render for all cities
scan --render maps --multicity 
scan --render scan-calculations --multicity
Note

--parallel applies to tasks within each city, not across cities. Cities themselves always run one at a time.

7.4 What Happens Under the Hood

For each city in the list, the scan runner:

  1. Extracts the city’s AOI — either from a {city_name}/ subfolder in inputs/AOI/ (Option A) or from the multipolygon file (Option B, which writes shapefiles to inputs/AOI/{city_slug}/)
  2. Auto-detects the .shp file inside that subfolder
  3. Generates a city_inputs.yml combining shared settings, any city-specific overrides, the detected AOI_shp_name, and a bm_cities_manual list populated with the other cities
  4. Writes that city_inputs.yml to inputs/ and runs scan as a subprocess
  5. The normal single-city flow takes over: creates mnt/{scan_id}/, copies AOI and wards files flat into 01-user-input/, and runs the enabled tasks
  6. Moves on to the next city

7.5 Output Structure

Each city produces its own self-contained folder under mnt/:

mnt/
  2026-04-namibia-windhoek/
  2026-04-namibia-swakopmund/
  2026-04-namibia-walvis_bay/
  2026-04-namibia-luderitz/
  2026-04-namibia-aus/

The bm_cities_manual field links each city to its siblings, enabling cross-city population comparisons in the worldpop analysis.
